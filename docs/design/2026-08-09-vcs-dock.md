# Repository dock — making the agent's edits visible and reversible

Date: 2026-08-09
Status: approved, ready for implementation planning
Location note: docs/superpowers is gitignored in this repo, so this lives under docs/design/

## Why

Hypheus can already checkpoint and roll back the agent's file edits: `pkg/agent/tools/vcs`
drives Jujutsu, whose operation log restores a whole tree atomically, bringing back files the
agent deleted and discarding ones it created. That capability shipped in crowe-terminal #89.

It is invisible. Only the agent can reach it, as tool calls over the local HTTP bridge. The
person whose files are being edited has no way to see what changed or to take it back. The
strongest safety property in the product is one nobody can observe.

This adds a dock panel that answers a single question: **what just changed, and how do I undo
it.**

## The unlock

Four apparently separate jobs — a safety net, a repository panel, a timeline, a live ticker —
are four views of one data structure. jj's operation log already carries a timestamp, a
description, and a restorable tree state per entry, and the working copy is simply the newest
entry. One data model yields all four affordances, so the panel does not need four features.

## Constraint

The dock drawer is 360px wide. That rules out side-by-side diffs and forces a single column.
The design leans into it rather than fighting it.

## Architecture

The jj-driving core currently lives inside `pkg/agent/tools/vcs`, reachable only through the
agent bridge. The frontend cannot use it there: wrong layer, and it would need the agent auth
key.

Extract the core into a shared Go package. Two callers consume it:

1. The existing `vcs.*` agent tools (behavior unchanged).
2. Three new wshrpc commands for the frontend.

One implementation of "how we talk to jj", two consumers, no duplicated argv handling or
error translation.

### New RPC surface

Defined in `pkg/wshrpc/wshrpctypes.go`, implemented in `pkg/wshrpc/wshserver.go`, clients
regenerated with `task generate` per the repo's `add-rpc` skill.

| Command | Purpose | Mutating |
|---|---|---|
| `VcsStatusCommand` | Working-copy state for a directory: changed file list, clean flag | no |
| `VcsHistoryCommand` | Recent operations: id, description, relative time | no |
| `VcsRestoreCommand` | Restore the tree to an operation id | yes |

Requests carry the target directory. Responses reuse the shapes the agent tools already
return so both paths stay in step.

## The surface

A single column in the drawer:

- **"Now" row, always first.** File count and a restore control. This is the live ticker; it
  needs no separate feature.
- **Operation list below.** Per row: label, relative time, restore action.
- **Selecting a row expands its changed files inline**, with +/- counts. Full diffs stay
  collapsed — they do not fit in 360px, and in the moment someone opens this panel they want
  to know *what* changed and undo it, not read a patch.
- **Rail affordance.** The dock icon carries a gold pip when the tree is dirty. Ambient
  awareness at zero chrome cost, and the reason a separate ticker view is unnecessary.

Scrolling the list is scrubbing. There is no separate timeline widget.

## Data flow

On panel mount, fetch status and history for the active block's working directory, falling
back to the workspace root. Refresh on panel focus and after any restore.

Poll rather than wire a WPS event for the first version. `jj status` is cheap, the panel only
matters while visible, and a pub/sub channel is real work to justify for a surface that is
closed most of the time. Revisit if polling proves visibly stale.

## Error handling

These states carry more weight than usual, because the panel is what someone opens when they
are worried.

- **jj not installed** is a normal state, not an error. Say so plainly, offer nothing else.
  The agent tools already gate registration the same way.
- **Directory is not a repository**: offer to initialize. `vcs.init` creates a local store
  with no remote, so this sends nothing anywhere.
- **Restore fails**: surface jj's own message verbatim. Those messages are good, and
  paraphrasing loses information exactly when the user needs it.

Restore is the only mutating operation in the surface.

## Scope

Deliberately excluded: commit, push, branch, merge, conflict resolution, diff viewing. Those
belong in the terminal two inches away. The panel does one job.

## Testing

- Go tests move with the extracted package; existing `vcs` coverage carries over, including
  the end-to-end test that wrecks a tree and restores it.
- Handler tests for the three RPC commands.
- A `vcs.preview.tsx` in the preview harness. The harness renders correctly as of
  `34d21b72`, which fixed its missing token and glass imports.

## Risks

- **Extraction touches shipped code.** The agent tools merged hours ago; the extraction must
  be behavior-preserving, and their tests are the guard.
- **Polling could feel stale** during rapid agent edits. Acceptable for v1; the upgrade path
  is a WPS event.
- **Which directory** the panel targets is a real ambiguity in a multi-block workspace. The
  active block's cwd with a workspace-root fallback is the starting rule; it may need a
  visible indicator so the user always knows which repository they are looking at.
